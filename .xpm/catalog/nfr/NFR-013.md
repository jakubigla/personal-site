## Constraint
Deployment from GitHub Actions reaches AWS only through OIDC federation with a role scoped to this repository; no long-lived access keys exist anywhere (repo, CI secrets, local files).

## Acceptance
- AC1: The deploy workflow uses OIDC (id-token write permission and role assumption); no AWS access key id or secret appears in workflow files or repository secrets.
- AC2: The IAM role trust policy restricts the subject to this repository and to the main branch (or its deploy environment).
- AC3: The role's permissions are limited to what deploy needs (writing the site bucket and invalidating the distribution).
- AC4: A secret scanner runs in CI and fails on any committed credential.
