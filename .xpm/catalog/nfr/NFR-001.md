## Constraint
On a mid-range phone the page scores Lighthouse 95 or more in performance, accessibility, best practices and SEO, its Largest Contentful Paint is under 2.5 s, and the total JavaScript shipped is kept small enough to hold both targets with the full motion system enabled.

## Acceptance
- AC1: A Lighthouse run with mobile emulation (mid-range phone profile) against the production build scores 95 or more in each of performance, accessibility, best practices and SEO.
- AC2: The same run reports an LCP under 2.5 s.
- AC3: A JavaScript size budget for the page is declared in the repo and checked automatically in CI; a build over budget fails the check.
- AC4: The checks run against the build with all motion acts enabled, not a stripped variant.

## Notes
The brief leaves the exact JS byte budget open ("small enough to meet that"); the architecture stage sets the number. The design gate also asks for a JS size and frame-rate reading of the Act 1 and Act 2 prototype on a mid-range phone.
