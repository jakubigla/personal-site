## Constraint
CI splits build and deploy: build and test jobs hold no id-token permission and hand the site over as an artifact; only the deploy job may request the OIDC token, and it runs no package install. Every third-party action is pinned by commit SHA, and installs use the lockfile with install scripts disabled.

## Acceptance
- AC1: The build and test jobs declare no id-token: write permission; only the deploy job does.
- AC2: The deploy job downloads the built artifact and runs no npm, pnpm or yarn install step.
- AC3: Every 'uses:' reference to a third-party action in .github/workflows is pinned to a full 40-character commit SHA, checked in CI.
- AC4: Dependency installs run from the lockfile with lifecycle scripts disabled (e.g. npm ci --ignore-scripts).
- AC5: Negative: a workflow change that grants id-token: write to a job that installs packages, or references an action by tag or branch, fails the CI check.

## Notes
Mitigates T-1 (infra / CI deploy role): a compromised npm package or GitHub Action could request the OIDC token and overwrite the live site. Complements NFR-013, which scopes the role but not what runs beside it. autopilot decisions batch, Q19.
