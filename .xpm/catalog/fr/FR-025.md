## Capability
Merging a PR to main builds, tests and deploys the static site to its AWS hosting, so Jakub's content edit goes live without any manual step.

## Acceptance
- AC1: Every pull request, docs-only ones included, runs the build and test pipeline.
- AC2: A merge to main builds, tests and deploys the site, and the change is served from the live domain afterwards.
- AC3: A failing build or test on main stops the deploy and leaves the previous version live.
- AC4: The deploy authenticates to AWS through GitHub OIDC; no long-lived key exists in the repo or its CI settings.
- AC5: A change merged to main is served from the live domain within 10 min of the merge.
- AC6: The deploy job waits for the CloudFront invalidation to complete and reports success only after it has.
- AC7: Content-hashed assets are served with Cache-Control "public, max-age=31536000, immutable", and HTML is served with a max-age of 300 s or less.
- AC8: A deploy uploads the new hashed assets before the HTML and keeps the previous release's hashed assets in the same run, so a visitor holding the old HTML still loads every asset it references.

## Notes
The first terraform apply and the DNS cut-over are attended steps by Jakub; autopilot does not deploy. Hosting, OIDC and CI-on-every-PR details are constraints and enablers.

Elicitation 2026-11-27 Q7: live within 10 min, with an awaited invalidation, long cache on hashed assets and short cache on HTML. The 300 s HTML max-age is a proposed default that architecture may tune within the 10 min window.

Rollback of a bad release is a revert and redeploy within 1 h (NFR-030). A failed deploy emails Jakub (NFR-032).
