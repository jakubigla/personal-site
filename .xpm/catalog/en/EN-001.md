## Outcome
Stand up the static site build with the framework chosen at architecture, and the single structured content file with its schema and section flags, so one value travels from the content file through the build into a plain static HTML page. The skeleton renders a minimal hero and footer from the content file, honours a section flag, and ships with the reserved, flagged-off "How I deliver" slot, giving every later section a place to plug in without touching layout code to change a fact.

## Acceptance
- AC1: A single build command produces a directory of plain static files (HTML, CSS, assets) with no server runtime needed to serve them.
- AC2: The content file is validated against its schema during the build, and an invalid file (missing required field, unknown section flag) fails the build with a readable error.
- AC3: Changing the headline text in the content file and rebuilding changes the rendered hero without any edit to layout code.
- AC4: Turning a section flag off in the content file removes that section from the built HTML; the "How I deliver" flag exists and is off by default.
- AC5: The built page is readable top to bottom with JavaScript disabled.
- AC6: A local test run (unit or build check) passes against the skeleton.

## Notes
Framework and content-file format are decided in the architecture stage. Selected-work entries use anonymized labels only; no real client name may enter the content file or any fixture.
