## Outcome
Provide the delivery path: GitHub Actions workflows that build and test the site on every pull request, docs-only ones included, and on merge to main build, test and sync the static output to the hosting bucket and invalidate the CloudFront cache, reaching AWS only through an OIDC-federated role with no long-lived keys anywhere. The IAM role and its trust policy are defined in Terraform and scoped to this repository and the main branch.

## Acceptance
- AC1: A pull request, including one that changes only documentation, triggers the CI workflow and it reports a status check.
- AC2: CI passes on main for the walking skeleton build and tests.
- AC3: The deploy job authenticates to AWS by assuming an OIDC role; the repository and workflows contain no AWS access keys or other long-lived secrets.
- AC4: The OIDC role trust policy is restricted to this repository and the main branch, and its permissions are limited to the site bucket and the distribution invalidation.
- AC5: On merge to main the workflow syncs the build output and creates a CloudFront invalidation (verifiable once the attended first apply has run).

## Notes
Deploy steps are inert until the owner completes the attended first apply. Workflow logs must never print client names or secrets.
