## Outcome
Add automated quality gates to CI so the performance, accessibility and weight targets are enforced on every pull request rather than checked by hand: Lighthouse runs against the built static site with a mobile profile, an automated accessibility scan runs in both colour themes, and a budget check caps the total shipped JavaScript and flags any request to a third-party origin.

## Acceptance
- AC1: A Lighthouse CI run on every pull request asserts a score of 95 or more for performance, accessibility, best practices and SEO, with a mobile profile, and fails the check below that.
- AC2: The Lighthouse run asserts LCP under 2.5 s and fails the check above it.
- AC3: An automated accessibility scan (WCAG 2.2 AA rules) runs on the built page in light and dark themes and fails on any violation.
- AC4: A JavaScript size budget is enforced on the build output and the check fails when it is exceeded.
- AC5: A check fails when the built page references a script, font or other runtime resource from an external origin, or sets a cookie.

## Notes
The exact JavaScript budget is set at architecture, informed by the motion prototype reading from the design gate.
