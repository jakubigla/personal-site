## Outcome
Define the hosting baseline as Terraform: a private S3 bucket served only through CloudFront with origin access control, an ACM certificate, Route 53 records in the existing zone, HTTPS only with HTTP redirected, security headers set at CloudFront, a custom 404 response and a www-to-apex redirect, all within a running cost under 2 USD per month. The code is fully validated and planned by automation; the first apply and the DNS cut-over remain an attended step by the owner.

## Acceptance
- AC1: terraform fmt -check and terraform validate pass for the hosting stack.
- AC2: A static policy or plan check confirms the bucket blocks all public access and is readable only by the CloudFront distribution through origin access control.
- AC3: The CloudFront configuration redirects HTTP to HTTPS, attaches a response headers policy (HSTS, CSP, X-Content-Type-Options, Referrer-Policy, frame protection) and serves the custom 404 page for missing paths.
- AC4: A request to the www host is configured to redirect to the apex domain.
- AC5: The stack declares no always-on compute, NAT gateway or WAF plan.
- AC6: A runbook in the repo describes the attended first apply and the DNS cut-over from the current page.
- AC7: An AWS Budgets monthly budget of 2 USD with email notifications at 80% and 100% of actual spend is defined, to the contact address the page publishes (NFR-034, NFR-014 AC2).
- AC8: CloudFront standard and real-time logging are off and no log store exists; Checkov custom policies in infra/policies fail a change that adds a WAF, NAT gateway, always-on compute or logging, or removes the budget (NFR-019 AC3, NFR-031 AC3, NFR-034 AC4).
- AC9: Remote state lives in a versioned, encrypted S3 bucket with native locking, created by a separate bootstrap root; no state file, account id or secret is committed (ADR-0009, NFR-014).
