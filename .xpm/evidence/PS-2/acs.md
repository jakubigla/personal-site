# PS-2 acceptance criteria

Source: taken from the ticket as written.

## Acceptance Criteria

- AC1: A single build command produces a directory of plain static files (HTML, CSS, assets) with no server runtime needed to serve them. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC1)
- AC2: The content file is validated against its schema during the build, and an invalid file (missing required field, unknown section flag) fails the build with a readable error. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC2)
- AC3: Changing the headline text in the content file and rebuilding changes the rendered hero without any edit to layout code. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC3)
- AC4: Turning a section flag off in the content file removes that section from the built HTML; the "How I deliver" flag exists and is off by default. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC4)
- AC5: The built page is readable top to bottom with JavaScript disabled. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC5)
- AC6: A local test run (unit or build check) passes against the skeleton. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC6)
- AC7: [needs-secret: DENYLIST] Foundation (outcome): the seat writes the repo's CI, task runner, hooks and dependency-update config for this stack itself (practice xpm/foundation-sized-to-project), every version from `xpm latest`, each tool configured once. Proven by running it, on the PR: - the documented command (README.md `## Run locally`) runs the stack on a clean clone; - CI runs on the PR and publishes the one required check `ci-ok`, green; - the secret scan runs: `.pre-commit-config.yaml` lists xpm-sensitive-scan and xpm-sensitive-scan-push, `xpm init hooks` installed them, and `pre-commit run --all-files` passes over every file, old files included; - dependency updates are configured for every ecosystem the repo uses, GitHub Actions included; - the exercising profile (`xpm paths committed surfaces`, shaped like `$(xpm root)/docs/exercising.example.md`) names every surface the ACs run on, and `xpm exercising_profile.sh validate` exits 0; - runtime versions the brief or an NFR names (none) are the ones the project pins. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC7)
- AC8: Foundation (judgment): for each component web and infra, the module layout, the first ADRs, the import boundaries and how much CI it gets follow its tier and its blueprint's knowledge, if it has any: read every file `xpm blueprint knowledge --paths` prints (each component's blueprint notes for its stack and tier, plus `repo`'s, which bind every component). ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC8)
- AC9: Local run: one documented command starts the whole stack locally, verified on a clean clone of main with nothing exported: whatever a fresh clone needs (installs, a non-secret local value for every variable the app reads, synthetic data only - no real or personal data) comes from the documented steps, never a README-only `export`. README.md's `## Run locally` section gives those steps in order, every loopback URL the stack serves and how to stop it. The local-run check runs the recorded tasks on a clean clone and probes each loopback URL in the section body (to its first `###`), https with no certificate check: another stack's URL goes under a `###`. The tasks are `mise run web:install` (setup), `mise run web:dev` (start, serving http://localhost:4321) and `mise run web:test` (tests). ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC9)
- AC10: Main regression: .github/workflows/ci.yml runs the full test suite, Playwright included, on every pull request and every push to main, in job web ([ADR-0016](https://github.com/jakubigla/personal-site/blob/main/docs/adr/0016-main-regression-job-ci-web.md)); the deploy job needs it. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC10)
- AC11: The skeleton follows the module map and walking skeleton of docs/architecture.md: apps/web (Astro, content/en.yaml with its Zod schema) and an infra root that passes fmt, validate and tflint with no cloud credentials; the deploy job exists and is skipped while the deploy role variable is unset. ([EN-001](https://github.com/jakubigla/personal-site/blob/main/.xpm/catalog/en/EN-001.md) AC11)
- AC12: Negative: a content file or fixture holding a term from the client-name denylist fails the CI denylist check without printing the term, and the check fails closed when the denylist secret is missing ([ADR-0013](https://github.com/jakubigla/personal-site/blob/main/docs/adr/0013-client-name-denylist-secret-fail-closed.md)).
- AC13: Negative: content-file text that contains HTML markup or a script tag renders as escaped text in the built page, never as markup or script.
