- typecheck is tsc --noEmit over the .ts files only: .astro files are covered by the build and the Vitest build checks. TypeScript is pinned to 6.0.x because typescript-eslint 8.74.0 (latest) declares typescript `>=4.8.4 <6.1.0` and TypeScript 7 ships no JavaScript compiler API for it; move to 7 when typescript-eslint supports it.
- The denylist check fails closed with exit 2 whenever no list exists; only the local pre-commit hook passes --optional so a laptop without .denylist.local can still commit. CI never passes it, so CI stays red until the DENYLIST secret is set (RAID D-001).
- Playwright specs run with JavaScript disabled for the whole suite, and use astro preview --ignore-lock because Astro 7 preview otherwise refuses a second instance.
- The deploy job is gated on the DEPLOY_ROLE_ARN repository variable and only downloads the site artifact; the publish steps belong to the hosting work.
- The repo job runs gitleaks (mise-pinned, `mise run repo:secrets`) over the full git history on every pull request and main push, so NFR-014 AC1 and AC4 hold in CI and not only in the local hooks. `.gitleaks.toml` keeps the default rules and allows only the SHA-256 digests in xpm design records, which the generic-api-key rule otherwise flags.
- web runs eslint (`npm run lint`, part of `mise run web:lint`) with the ESLint and typescript-eslint recommended rules over the .ts, .js and .mjs files, as the web-frontend blueprint lists for the standard tier. The blueprint knowledge files for web, infra and repo (`xpm blueprint knowledge --paths`) were read: tiers, eslint, prettier, typecheck, vitest, Playwright and bundle-budget gates for web; fmt-validate and tflint for infra; the repo base practices. The rules-of-hooks part of the eslint gate does not apply: the site has no React.
- The JavaScript budget is a build check from the start: tests/build.test.ts sums the gzipped size of every script in the built page and fails above ADR-0005's 50 KB total or 1 KB render-blocking. The page ships no script today, so it passes with room; it is in place before the first script lands.
- Dependabot has no mise ecosystem, so the tool pins in mise.toml (node, terraform, tflint, pre-commit, gitleaks) and MISE_VERSION in ci.yml get no update PRs. They are refreshed by hand with `xpm latest mise <tool>` when a change touches them; an updater that reads mise.toml (Renovate's mise manager) needs the Renovate app installed on the repository, which is the PO's call.
